## Шаг 2.3 — поиск Redis

Compose подключает app и redis к общей пользовательской сети backend. Встроенный DNS Docker разрешает имя сервиса `redis` в адрес контейнера. В app явно задано `REDIS_HOST=redis`; `localhost` внутри контейнера приложения означал бы само приложение, а не соседний сервис. Для backend включено internal:true; Redis подключён только к ней и не имеет host-публикации порта. Приложение дополнительно использует ingress-сеть, чтобы Docker мог опубликовать его порт строго на loopback хоста.

## Шаг 3.2 — client в /whoami

При проверке с Windows реальной devops-vm получен ответ:

```text
scheme: https
client: 192.168.56.1
host: api.devops.local
```

client — адрес хостовой системы в Host-only, который nginx видит в $remote_addr и передаёт через X-Real-IP. TCP-соединение приложения установлено с nginx, поэтому TCP peer не содержит исходный адрес клиента. Nginx явно задаёт X-Real-IP, Host, X-Forwarded-Proto и X-Forwarded-For. Прямой сетевой доступ к app:8001 закрыт loopback-публикацией.
