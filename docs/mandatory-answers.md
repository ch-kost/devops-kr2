## Шаг 2.3 — поиск Redis

Compose подключает app и redis к общей пользовательской сети backend. Встроенный DNS Docker разрешает имя сервиса `redis` в адрес контейнера. В app явно задано `REDIS_HOST=redis`; `localhost` внутри контейнера приложения означал бы само приложение, а не соседний сервис. Для backend включено internal:true; Redis подключён только к ней и не имеет host-публикации порта. Приложение дополнительно использует ingress-сеть, чтобы Docker мог опубликовать его порт строго на loopback хоста.

## Шаг 3.2 — client в /whoami

При локальной HTTPS-проверке получен ответ:

```text
scheme: https
client: 172.21.0.1
host: api.devops.local
```

Значение client — адрес, который увидел тестовый Nginx в `$remote_addr` и передал через X-Real-IP. В локальном Docker Desktop стенде это адрес шлюза 172.21.0.1. На реальной devops-vm результат будет зависеть от её сетевой топологии. TCP-соединение приложения установлено с прокси, поэтому получить исходный адрес пользователя из TCP peer приложения нельзя. Nginx явно переопределяет X-Real-IP и передаёт Host, X-Forwarded-Proto и X-Forwarded-For.
