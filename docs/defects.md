# Ревизия исходного шаблона

Исходный коммит: `3ee6c4b` (`main` преподавателя). Номера строк относятся к нему. Значение исходного пароля не воспроизводится.

| № | Файл и строка | Дефект | Последствие при эксплуатации | Исправление |
|---|---|---|---|---|
| 1 | Dockerfile:1 | `python:latest` | Следующая сборка может получить другую основную версию Python и несовместимые зависимости | Использовать `python:3.12-slim`; подтвердить совпадение с образом ПР №7 на VM |
| 2 | Dockerfile:5 | `COPY . .` без исключений | В образ попадают `.env` и история `.git`, включая раскрытый секрет | Исключить через `.dockerignore`, копировать только необходимые файлы |
| 3 | Репозиторий, отсутствует `.dockerignore` | Секрет включён в контекст сборки | Даже неприменённые Dockerfile-файлы контекста передаются сборщику; секрет рискует попасть в слои | Добавить `.env`, `.git`, ключи и временные файлы в исключения |
| 4 | Dockerfile:5–6 | Исходники копируются до установки зависимостей | Любая правка `app.py` сбрасывает кэш `pip install`, повторно загружая зависимости | Сначала `COPY requirements.txt` и установка, затем исходники |
| 5 | Dockerfile, отсутствует `USER` | Процесс приложения работает от root | Уязвимость приложения даёт привилегированную учётную запись внутри контейнера и увеличивает последствия ошибки | Создать UID 10001 и задать `USER 10001:10001` |
| 6 | Dockerfile:9 | Shell-форма CMD | Между Docker и приложением появляется оболочка; SIGTERM может не попасть в Gunicorn, остановка затягивается до SIGKILL | JSON exec-форма `CMD ["gunicorn", ...]` |
| 7 | Dockerfile:9 | Bind на `127.0.0.1` внутри контейнера | Запрос с опубликованного порта приходит на сетевой интерфейс контейнера, на котором приложение не слушает | Gunicorn слушает `0.0.0.0:<порт>`; host mapping остаётся `127.0.0.1:<порт>:<порт>` |
| 8 | Dockerfile:8–9 | Порт 8000 вместо 8001–8004 | Конфигурация варианта и реальный слушающий порт расходятся, проверки возвращают отказ | Build arg/env `APP_PORT`, конфигурация Gunicorn, отдельный файл каждого варианта |
| 9 | .env:1 и отсутствие .gitignore | Пароль отслеживается Git | Любой читатель репозитория и его истории знает старый секрет; удаление последующим коммитом не отзывает его | Удалить `.env` из последнего состояния; `.gitignore` и `.env.example`; новый случайный пароль только на сервере |

Логика `app.py` и состав `requirements.txt` сохранены. Разрешённый комментарий `# KR2: Chugunov` добавляется отдельным коммитом для опыта с кэшем.
